# TASK 3 — CURRENCY SYSTEM MUST BE USER-SELECTED

The application currently has areas after login such as:

* Reports
* Insights
* Dashboard metrics
* Total Revenue
* Other financial summaries

These areas currently display currency using `$` / US Dollars by default.

This is not acceptable for an international invoice application.

The currency used throughout financial summaries must be based on the user's selected invoice currency.

## Required behavior

During invoice creation, the user chooses the invoice currency.

For example:

* USD
* EUR
* GBP
* PKR
* AED
* SAR
* INR
* CAD
* AUD
* Other currencies already supported by the application

Use the application's existing currency system if one already exists.

Do not create duplicate currency systems.

The selected currency must be stored with the invoice.

The selected currency must be available when calculating and displaying financial metrics.

## Dashboard / Reports / Insights behavior

When displaying:

* Total Revenue
* Revenue summaries
* Invoice totals
* Reports
* Insights
* Financial metrics
* Other monetary values

Do not hardcode `$`.

Do not assume USD.

Use the currency associated with the relevant invoice data.

If the dashboard is displaying a combined total containing invoices with different currencies, DO NOT incorrectly add different currencies together.

Instead, use one of these safe approaches:

1. Group totals by currency.

Example:

USD $1,000
EUR €500
PKR Rs. 100,000

OR

2. If the application already has a reliable currency conversion system, use it correctly.

Do NOT implement fake currency conversion or use hardcoded exchange rates.

For the MVP, grouping totals by currency is safer than incorrectly combining different currencies.

## Important

The currency symbol and formatting must be dynamically determined.

Examples:

USD → `$`

EUR → `€`

GBP → `£`

PKR → `Rs` or the existing appropriate locale format

AED → `د.إ` or the appropriate supported format

Do not hardcode `$` anywhere that should dynamically reflect invoice currency.

Search the codebase for hardcoded dollar currency formatting and fix relevant financial displays.

Do not change unrelated text that legitimately uses `$`.
