PHASE 2 — ROUTING DECISION RULES
==================================================

Apply these rules strictly.

CASE A — VALID CURRENT PAGE

Keep it.

Do not redirect it.

Ensure:
- HTTP 200
- self-referencing canonical where appropriate
- unique title
- unique meta description
- one primary H1
- included in sitemap if it is an indexable public page

CASE B — VALID PAGE BUT BROKEN

Fix the route.

Do not create a redirect if the URL itself is intended to remain valid.

Verify:
- HTTP 200
- correct content
- correct canonical
- correct metadata
- one H1
- sitemap inclusion if appropriate

CASE C — OLD URL WITH CLEAR REPLACEMENT

Create a permanent 301 redirect to the closest relevant canonical page.

Do NOT redirect everything to the homepage.

Example:

/old-invoice-generator
→ /invoice-generator

Only use a redirect when the replacement is genuinely equivalent or clearly serves the same search intent.

CASE D — OLD/REMOVED URL WITH NO REPLACEMENT

Do NOT invent a replacement page.

Prefer a proper 410 Gone response if the route is definitely obsolete and has no useful successor.

If the existing deployment architecture cannot safely produce 410 responses, document the limitation and use the safest available production approach.

Do NOT create fake SEO pages just to eliminate 404s.

CASE E — PRIVATE/PROTECTED ROUTE

Do NOT expose it publicly.

Examples may include:
- /dashboard
- /dashboard/*
- /profile
- authentication routes
- internal application routes
- private workspace routes

Ensure these are not included in the public sitemap.

Do not alter authentication behavior.

CASE F — DUPLICATE URL

Keep one canonical URL.

Redirect duplicate public URLs to the preferred canonical URL when appropriate.

Do not create multiple nearly identical SEO pages.

CASE G — INVALID/GARBAGE URL

Do not create a page for it.

Do not add it to the sitemap.

Return 404 or 410 according to the situation.

CASE H — UNKNOWN

DO NOT make assumptions.

Add it to the final report under:

"Requires Human Review"

and explain why.
